1. **New — an ACSC alert and a third-party report of the same alert are left as two separate stories, and the code structurally can't group them.** `"Vulnerabilities are moving quickly, so patch, protect, prevent"` (ACSC via Google News, `official: true`, 2026-11-17T12:00Z, no threat level by design) and `"ACSC warns vulnerabilities are being exploited quickly, urges organisations to patch and reduce exposure"` (Australian Cyber Security Magazine, 2026-11-17T23:44Z) are the same ACSC advisory — ACM's own summary opens "The Australian Signals Directorate's Australian Cyber Security Centre (ACSC) has issued a critical alert warning organisations that unpatched software vulnerabilities are being exploited rapidly…", directly describing the Google News item. They show as two unrelated stories. Root cause, verified in code: `validate_groups()`'s shared-name check (`scripts/stories.py:113-116`) only keeps a pairing if both members share a capitalised name/number drawn from `subject_words()` (title + first sentence). The ACSC item's own title/summary never contains the word "ACSC" — Google News strips ACSC's institutional framing, leaving only "cyber.gov" (lowercase, not a name) — so it can never share a name with ACM's title, which does say "ACSC". This means **no** official ACSC item can ever be matched to a third party's report of it under the current rule, even when the AI model pairs them correctly. Worth a structural fix (e.g. treat `official: true` as sharing a name with any title containing "ACSC"), not a one-off miss.

Cause: the Cyber tag's keyword regex (`scripts/fetch_cyber_news.py:291`, built by `_keyword_regex()` at lines 468-474) matches "hack" plus an "-ing" suffix as a whole word, and **Port Hacking** (a real bay south of Sydney) contains "hacking" as a standalone word, so the place name trips the hacking keyword. Same class of bug as the "actor"/"threat actor" fix already in place — worth a similar exception for place names ("Port Hacking", "Port Macquarie", etc.). Not prominent on the live site (buried among 94 items, no further effect since it already carries a `Cyber` tag from a real source), but it is exactly the "clearly wrong tag" check this report is asked to run.
